# 校验设计

## 设计原则
校验**不得复用 `classify()`**，否则分类 bug 会导致移动与校验同向出错，产生虚假的「100% 正确」。正确做法是「不变式检查」，两条独立代码路径

## 校验函数（评判标准，关键设计）
- **移动侧**：`classify(file) -> 目录名`（属性 → 目录名，正向）。
- **校验侧**：`folder_to_constraint(目录名) -> 属性约束`（目录名 → 属性范围，逆向）。
  从目录名解析出语义约束，再用文件**原始属性**直接比对：
  - `jpg/` → 要求 `file.suffix.lower() == ".jpg"`；
  - `no_extension/` 要求 `Path(file).suffix == ""`；
  - `lt1MB/` → 要求 `st_size < 1MB`；
  - `1MB-10MB/` → 要求 `1MB <= st_size < 10MB`（左闭右开）；
  - `ge10MB/` → 要求 `st_size >= 10MB`；
  - `2026/` 要求 ytime 落在2026
  - `2026-10/` → 要求 ytime落在2026且mtime 落在10月
  - `2026-10-2/` 要求 ytime落在2026且mtime 落在10月且dtime落在2。
**两侧只共享「目录命名约定」，`folder_to_constraint`是从目录名称字符串反向解释语义，与 移动侧`classify`函数不共享分类计算逻辑**，因此 classify 的边界/取值 bug 会被校验抓住。

## 校验报告格式
输出结构：
- 总数：扫描到的所有文件数，包含未分类的文件
- 正确数：落在正确分类目录中的文件数
- 错误数：落在错误分类目录中的文件数
- **未分类/遗漏数**：落在任何分类目录之外的散落文件数
- 错误明细：每条包含：路径 + 实际属性 + 违反的约束。
- 正确率 = 正确数 / 总数。

## 完整性检查
- 除检查子目录内文件，还要扫描落在任何分类目录之外的散落文件，单列「未分类」报告。
- 对于无法解析的目录名，给出警告并忽略此目录的校验
- 如果 --output 指定了不同目录，需同时检查原始目录中的残留文件

## 残余局限
校验能抓「放错目录」和「漏分类」，但抓不了「目录命名约定本身错误」这类规范级问题。
